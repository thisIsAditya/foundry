# Lean Startup (Eric Ries)

**Source:** _The Lean Startup_ (2011), built on Blank’s Customer Development and lean manufacturing.

## The premise

The unit of progress for a startup is **validated learning**, not features shipped or code written. You write down leaps of faith, build the smallest experiment that tests them, measure, and learn — then pivot or persevere.

## Build–Measure–Learn

- **Build** the smallest artifact that can test the hypothesis (often not the product: a landing page, a concierge service, a video).
- **Measure** against a metric you declared _before_ seeing the data (otherwise you will move the goalposts).
- **Learn** whether to change the customer, the problem, the solution, or the model.

The loop should be as short as possible. Speed of learning is the advantage (Maurya says the same).

## MVP, correctly

Ries’s MVP is **not** “v1 with fewer buttons.” It is the fastest way to start the learning loop. A concierge MVP (you perform the service manually) is a valid MVP. A fake door test is a valid MVP. A six-month “platform” is usually not.

This is where developers go wrong, and where naive coding agents go wrong.

## Accounting

Ries argues against vanity metrics (signups, page views). Use **actionable, accessible, auditable** metrics. Cohort analysis beats cumulative graphs. AARRR (Pirate Metrics: Acquisition, Activation, Retention, Referral, Revenue) is the later operationalization.

## Pivot types (useful critic vocabulary)

Zoom-in, zoom-out, customer segment, customer need, platform, business architecture, value capture, engine of growth, channel, technology. The critic agent should name the pivot, not just say “maybe pivot.”

## What to encode

- Every MVBP has a **written hypothesis and a kill metric**.
- Manual / concierge paths are first-class, especially in India services and ops-heavy B2B.
- Dashboards in Phase C hide vanity metrics by default.

## What not to encode

- “Ship daily” as a virtue when the bottleneck is interviews, not CI.
- Using “pivot” as a euphemism for flailing. A pivot changes one core hypothesis and keeps the rest.
