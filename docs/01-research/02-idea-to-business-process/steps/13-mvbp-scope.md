# Step 13 — MVBP / MVP scope

**Phase:** 3  
**Sources:** Ries MVP; Aulet 22 MVBP; Cagan’s five questions; Blutrich ONE feature test; starter notes (“smallest thing that tests the core hypothesis”).

## Definitions

| Term     | Meaning                                                                                            |
| -------- | -------------------------------------------------------------------------------------------------- |
| **MVP**  | Smallest artifact that starts validated learning (can be manual).                                  |
| **MVBP** | Smallest artifact where the customer **gets core value, pays, and you can learn**. Default for us. |

## How to scope

1. Write the **core hypothesis** in one line (problem + customer + value + pay).
2. List every feature the vision wants.
3. Keep the **one** capability without which the hypothesis cannot be tested.
4. Everything else is `out_of_scope.md`.
5. Prefer concierge / wizard of oz if software would take > 2–4 weeks.
6. Answer Cagan: Can they use it? Would they? Can we build it? Is it viable? Should we (ethics)?

Marty Cagan via practitioners: a 100% manual process with **no path** to a product is wishful thinking if you claim to be a software company — but a **time-boxed** concierge to test demand is correct.

## Evidence required

- Gate A passed. Gate B preferably passed.
- Written out-of-scope list.
- Time box (Blutrich: one week for a software slice when using AI builders; longer if hardware/regulated).

## Common failure modes

- “MVP” with 4+ features (instant fail in Blutrich guardian — keep that fail).
- Rebuilding the competitor’s full suite.
- No payment path, so you learn nothing about MVBP.
