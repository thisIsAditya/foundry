## Primary sources read

| Source                                                                                                                                                                                                                                                                                                     | What we took                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Anthropic — Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) (Dec 2024)                                                                                                                                                                                        | Workflow vs agent. Prompt chaining, routing, parallelization, orchestrator-workers, evaluator-optimizer. Start simple; add multi-agent only when a single augmented LLM fails.                                                                                                                                                                                      |
| [Anthropic — Multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system) (Jun 2025)                                                                                                                                                                                    | Lead + parallel subagents. Plan written to external memory. Subagent brief = objective + output format + tools + boundaries. Vague delegation duplicates work. Workers return condensed findings. Fetch is data, not instructions. Strong lead / cheaper workers. ~15× token cost vs chat — task must justify it. Sync workers chosen to contain error propagation. |
| [Microsoft Magentic-One](https://www.microsoft.com/en-us/research/articles/magentic-one-a-generalist-multi-agent-system-for-solving-complex-tasks/) (Nov 2024) + [Agent Framework Magentic orchestration](https://learn.microsoft.com/en-us/agent-framework/workflows/orchestrations/magentic) (docs 2026) | Task ledger (facts, guesses, plan) + progress ledger (satisfied? loop? progress? next speaker? instruction?). Stall → replan. Caps on rounds/stalls/resets. Optional human plan review. Ablation: ledgers matter (~31% drop without).                                                                                                                               |
| [OpenAI — Orchestration and handoffs](https://developers.openai.com/api/docs/guides/agents/orchestration) + [HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)                                                                                                                       | Handoff = specialist owns the next reply. Agents-as-tools = manager keeps the reply. Durable pause/resume for approvals.                                                                                                                                                                                                                                            |
| Supervisor vs swarm (2026 practitioner synthesis, e.g. [dreaming.press](https://dreaming.press/posts/multi-agent-orchestration-supervisor-vs-swarm-vs-handoffs.html))                                                                                                                                      | Supervisor: legible, cost fans out. Swarm: cheaper, weaker audit. Fan-out pays only when shards do not need to talk mid-flight.                                                                                                                                                                                                                                     |
| Four topologies (pipeline / parallel / hierarchical / debate) — 2026 engineering write-ups                                                                                                                                                                                                                 | Pipeline compounds errors. Debate context grows multiplicatively; sycophancy and oracle-gap at vote time. Hierarchical needs memory _outside_ the window.                                                                                                                                                                                                           |
| [Dynamic coordination strategy selection](https://arxiv.org/html/2606.00804v2) (2026)                                                                                                                                                                                                                      | Do not pick one global coordination strategy. Structured compliance / deterministic checks → single agent. Debate only for adversarial conflicting-objective decisions.                                                                                                                                                                                             |
